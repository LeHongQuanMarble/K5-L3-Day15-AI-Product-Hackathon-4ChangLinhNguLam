## 2. Kiểm thử runtime (chạy thật qua HTTP)

Server chạy từ gốc repo, `MODEL_PROVIDER=fake` (để smoke nhanh, không tốn token; Real AI đã kiểm chứng riêng ở T14/T18):

```
python ailab/server.py                                  # 127.0.0.1:8800
ADMIN_PASSWORD=<password local> bash ailab/smoke.sh      # TẤT CẢ QUA
```

Kết quả smoke (10 nhóm, **mọi bước ✓**, thoát 0):

- `/health` 200; login Admin/User; User bị chặn Admin 403.
- Tạo model/player/app: 201; link sai (http thường), HTML thiếu `jl-camera`, app thiếu ô bắt buộc → 400.
- `GET /api/apps/<id>/play` → 200 **và có header `Content-Security-Policy`** (mở không cần đăng nhập).
- Chatbot: đề xuất `pending`, **không mang HTML thô**, có `flags`, `GET .../proposals/<idx>/try` 200 (xem thử sandbox); accept → player `draft`; accept lần 2 → 409; reject → không lưu gì.
- HITL: User tự approve → 403; Admin approve → 200; game xuất hiện ở `scope=community`.
- Bộ đề: tạo/sửa/xoá, câu hỏi truyền vào app chơi bản mới, đề có sẵn 15 câu không sửa/xoá được.

Ngoài ra T14 đã kiểm chứng runtime **Real AI** (`gpt-4o-mini`) qua HTTP: `/api/agent` 200, trace token > 0; `/api/agent/publish` 400/403 khi tự duyệt và 200 khi có phê duyệt rõ ràng; `/api/agent/review` đổi nội dung → `draft`. Chi tiết: `docs/T14-integration.md`. Evaluation Run 1 (`eval/run-1.csv`, 30 câu) là bằng chứng Real AI có token usage thật.

### Mouse Fallback ở runtime

`ailab/web/play.js` xử lý mọi đường lỗi camera bằng `mouseHint()` (dòng 20–21, 75–76, 94) và `stop()` báo "Camera đã tắt — đang chơi bằng chuột" (dòng 98–103); luồng chơi bằng chuột luôn bật, không phụ thuộc model. Đây là bằng chứng **code + smoke HTTP**; việc bấm thử trong trình duyệt với camera bị từ chối cần TV3 ghi hình (mục 4).
